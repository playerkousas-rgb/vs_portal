## ④ 先講最痛嗰單：寫入自證（唔會再有「假成功」）

### 之前點解會「寫入成功、核對對唔上」

逐表寫（`saveTables`）嘅流程係「先寫新、後刪舊」：寫晒新行 → 刪走舊嗰套 → 回 success。
但中間有個空隙冇人驗收 —— 如果刪舊嗰步手快快連新行都掂到、或者另一部機同時寫緊、
或者後端部署根本唔係 v2.8.0，後端照回 success，前端照當成功，收據隔幾秒再問先發現係空。
團長見到嘅「寫入版本 `Smug9od9v-77036`、後端大小 2B、各表後端皆冇」就係咁嚟：
**寫入嗰下後端話收到，但留唔到行**，之前冇人喺嗰一刻捉住佢。

### 改成點（後端 v2.8.1 ＋前端）

1. **後端寫完即刻讀返**（`saveTables` 最後一步）：數返「資料表」分頁呢個旅團有幾多行、
   邊啲表齊料。齊先回 `confirmed: true`；唔齊就回 `confirmed: false`＋爭邊啲表，
   **寫入當場就叫失敗，唔等收據先發現**。
2. **前端唔認假成功**：逐表寫冇 `confirmed: true` 就係失敗（`not_confirmed`），
   未儲存嘅改動原封不動留喺部機，唔會以為存好咗。錯誤訊息會叫你再撳一次儲存，
   試幾次都係咁就去對後端版本／重貼 Code.gs（見下面部署一節）。
3. **舊部署唔會斷**：v2.8.0 後端唔識自證（冇 `confirmed` 欄位）→ 照當成功，
   邏輯係「唔識答＝舊版，舊版按舊規矩」。但收據會如實寫「後端程式版本 v2.8.0」，
   等你知要升級。

## ② 「分頁有料、前端話冇」——報數而家講真相

之前 `dbInfo`（後端有乜嗰個查詢）只回「砌唔砌到一份完整資料」：砌唔到就 `found: false`，
但唔講分頁實際有幾多行。所以會出現團長嗰種情況：打開試算表見到「資料表」分頁明明有行，
但 app 話後端冇嘢 —— 其實係**有行但讀唔到**（例如 JSON 壞咗、版本唔啱），之前個回應分唔出。

而家 `dbInfo`／`diag` 一律如實報（就算 `found: false` 都照報）：

- `mode`：`simple`（逐表寫）／`blob`（舊整份）／`empty`（真係空）
- `simpleRows`／`blobRows`：「資料表」／「資料庫」分頁呢個旅團實際有幾多**行**
- `broken`：邊啲表壞咗（讀唔到嗰啲名）
- `backendVersion`：後端程式版本

「**後端實況**」頁（總表同步入面）同寫入後張**收據**都會show呢啲數。
以後見到「後端冇嘢」，一眼就分得出係「真係空（行數 0）」定「有行但讀唔到（行數＞0＋壞表名）」——
兩樣嘢嘅醫法完全唔同（前者係未寫入，後者要撳「修復後端」）。

## 追加（2026-11-12 更正）：Progress 只讀寫同一 Unified Sheet

先前將 Progress 描述成跨系統關係的設計已撤回。現行邊界是：

- Progress browser → 支部同源 `/api/progress` → 本支部 Unified `/exec`；
- `load`／`save`／`saveOtherBadge`／審批及個人 action 直接選取同一 Sheet 的進度分頁；
- server-side HMAC 只驗證向同一 `/exec` 發出的業務 action，不代表另一個系統；
- client、Progress API 及回應均沒有登入閘門、旅系統控制或整合狀態；
- 未來由旅系統單向讀支部後端，正如 BOOK 讀 BADGE，Progress 不參與該契約。

歷史 `PROGRESS*` 變數、browser backend／Key、入口開關及狀態卡均不是現行部署方式。

### ② 「B 機有未存資料 → 登唔到 A 機新開嘅帳戶」（已核實無需改 code）

### ③ 「我只係㩒來㩒去分頁，乜都冇掂過，佢周圍話有 1 份未完成草稿」（已修）

病根：`bindDraftAutosave()` 一入版就註冊咗 flush 入 `pendingFlushes`，而 flush 舊
寫法係**無條件** `saveDraft()`。所以「純粹入去、原封不動轉走」都會生成一份草稿，
`main.js` 轉分頁嗰陣用 `stashActiveDrafts()` flush 完見到有嘢，就彈
「呢個分頁有 1 份未完成草稿」。

改咗：`guard.js` 捉返「**入版嗰陣**」嘅欄位值做基準（baseline）；下次 flush 時
欄位同基準一比——冇變就**唔寫、唔報告**。真係改過先照舊暫存；改完又改返原樣都
唔會冤枉佢。另外 `bindDraftAutosave` 而家回傳 `{ stop, markDirty }`：

- `stop()` — render 拆除／轉分頁嗰陣解除監聽兼解除呢個分頁嘅草稿追蹤；
- `markDirty()` — 欄位值俾程式改咗（撳「還原」回填舊草稿、finance settings 入版
  回填舊草稿）嗰陣打，等下次 flush 唔會「以為冇改過」而掉咗。

回歸：新增 `tests/drafts.mjs`（12 項，已入 `npm test`，suite 而家 23 個）。全量
`npm test` EXIT=0。

### ④–⑤ Progress 邊界更正（舊入口控制設計已撤回）

舊版曾把登入閘門控制放入 Progress。現行實作已刪除相關 client helper 及
