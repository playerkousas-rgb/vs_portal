## ② 「分頁有料、前端話冇」——報數而家講真相

之前 `dbInfo`（後端有乜嗰個查詢）只回「砌唔砌到一份完整資料」：砌唔到就 `found: false`，
但唔講分頁實際有幾多行。所以會出現團長嗰種情況：打開試算表見到「資料表」分頁明明有行，
但 app 話後端冇嘢 —— 其實係**有行但讀唔到**（例如 JSON 壞咗、版本唔啱），之前個回應分唔出。

而家 `dbInfo`／`diag` 一律如實報（就算 `found: false` 都照報）：

- `mode`：`simple`（逐表寫）／`blob`（舊整份）／`empty`（真係空）
- `simpleRows`／`blobRows`：「資料表」／「資料庫」分頁呢個旅團實際有幾多**行**
- `broken`：邊啲表壞咗（讀唔到嗰啲名）
- `backendVersion`：後端程式版本

「**後端實況**」頁（總表同步入面）同寫入後張**收據**都會show呢啲數。
以後見到「後端冇嘢」，一眼就分得出係「真係空（行數 0）」定「有行但讀唔到（行數＞0＋壞表名）」——

## 追加（2026-09-25）：「VSBADGE 進度接駁連唔上」＋「B 機有未存資料登唔到 A 機新帳戶」

### ① 點解 VSBADGE 突然連唔上（調查結果）

查過 vsbadge 個 repo（最新一支 `apps-script/Code.gs`，旅系統升級）之後搵到真因：

進度前端（VSBADGE）近排升級咗做「**旅 > 團 > 進度**」。進度嗰支 GAS 多咗一個
「**本機直接入口**」掣（Script Properties `ALLOW_LOCAL_LOGIN`）。一旦有人喺掣度
「🔒 閂口（只收 sig）」：

- 舊式 **apikey 直連**（呢邊 `api/progress.js` 一直用嘅 `GET ?action=load&apikey=…`、
  `POST action=save + apikey`）會被拒，回：
  `{ success:false, upstream_only:true, error:"此後端的直接入口已閂（ALLOW_LOCAL_LOGIN=false），只接受上游簽名（sig）請求…" }`
- 以前經 ECPORTAL 直接 apikey 讀寫係通嘅，一閂口就全部「連唔上」——正正係今次個病徵。

（加分步查過：兩套共用分頁嘅欄序一致 —— `成員名單`＝`[YMIS, 姓名, …]`、
`進度追蹤`＝`[YMIS, 項目ID, 完成日期, 更新時間, 確認者, 備註]`，vsbadge 按欄 0/1 讀人、
按欄 0/1/2/4 讀進度，所以同一張 Sheet 讀得返 —— 接駁死因係閂口掣，唔係欄序。）

### 改咗啲乜（唔使改 VSBADGE，唔使經旅／團中間那支 GAS）

`api/progress.js` 而家**識得出 vsbadge 同一款簽名**：

```
linkSigKey = hex(HMAC-SHA256("vsbadge-troop-sig-v1", SHEET_KEY))     // SHEET_KEY＝進度後端自己條 API_KEY
canonical  = action + "\n" + ts + "\n" + nonce + "\n" + hex(SHA-256(rawBody))
sig        = hex(HMAC-SHA256(canonical, linkSigKey))
```

- **自動回退**：先照舊用 apikey；一收到 `upstream_only`，就自動轉去**簽名 POST**
  （body＋query 兩組 sig，同 vsbadge `callDownstream` 一模一樣）直打進度後端 `/exec`。
  關鍵係 vsbadge 嘅 `doPost` 喺「直接入口」掣**之前**先驗簽名，所以閂咗口都入得。
- `load`／`save`／`saveOtherBadge`／`reviewRequest`／`reviewLogRequest` 全部喺 vsbadge
  簽名白名單，所以讀／勾進度／審批中心照樣用得返。
- **只需一條嘢**：`TROOP_<編號>_APIKEY`（或 `_PROGRESSAPIKEY`）＝嗰張進度 Sheet 嘅
  SHEET KEY（Apps Script 執行 `showApiKey()` 攞嗰條）。有齊就自動接通，key 唔落瀏覽器，
  比起舊 apikey 直連仲硬淨。冇嗰條 key 嗰陣，前端照收到 `upstream_only` ＋點救嘅人話。
- 進度「設定 → 連線狀態」多咗一格**接駁方式**（API Key 直連／已接駁 VSBADGE 旅系統（簽名）／
  後端閂咗直接入口），讀唔到嗰陣會講明係閂咗直接入口、同埋要貼返 SHEET KEY。

> 註：vsbadge 最新版將團員自助申報改名做 `requestComplete`／`getPendingRequests`
> （我哋用開 `addRequest`／`myRequests`）——兩邊字眼唔同係個名差異，唔係接駁死因；
> 等我哋個「團員入口」對住 vsbadge 嗰張 Sheet 嗰陣，申報要行 vsbadge 嗰組名。

### ③ 「我只係㩒來㩒去分頁，乜都冇掂過，佢周圍話有 1 份未完成草稿」（已修）

病根：`bindDraftAutosave()` 一入版就註冊咗 flush 入 `pendingFlushes`，而 flush 舊
寫法係**無條件** `saveDraft()`。所以「純粹入去、原封不動轉走」都會生成一份草稿，
`main.js` 轉分頁嗰陣用 `stashActiveDrafts()` flush 完見到有嘢，就彈
「呢個分頁有 1 份未完成草稿」。

改咗：`guard.js` 捉返「**入版嗰陣**」嘅欄位值做基準（baseline）；下次 flush 時
欄位同基準一比——冇變就**唔寫、唔報告**。真係改過先照舊暫存；改完又改返原樣都
唔會冤枉佢。另外 `bindDraftAutosave` 而家回傳 `{ stop, markDirty }`：

- `stop()` — render 拆除／轉分頁嗰陣解除監聽兼解除呢個分頁嘅草稿追蹤；
- `markDirty()` — 欄位值俾程式改咗（撳「還原」回填舊草稿、finance settings 入版
  回填舊草稿）嗰陣打，等下次 flush 唔會「以為冇改過」而掉咗。

回歸：新增 `tests/drafts.mjs`（12 項，已入 `npm test`，suite 而家 23 個）。全量
`npm test` EXIT=0。

### ④ VSBADGE「閂門」由邊個話事（答架構問題，未寫 code）

你要嘅最終效果 —— 「執住 URL＋API KEY 嗰個人先可以關 VSBADGE 嘅門；關門要經
VS-PORTAL；只會控到**自己嗰支** VSBADGE 後端、唔會郁到其他團」——查咗 vsbadge
最新 `Code.gs`，結論係**技術上完全可行，而且 vsbadge 已經留咗位**：

- 閂門真正做嘅只有一件事：寫個 flag `Script Properties.ALLOW_LOCAL_LOGIN=false`。
  呢支後端 `doPost` 一行 `if(!localLoginAllowed()) return linkClosedResponse(action)`
  就封死所有 apikey／本地登入入口。**成個狀態就係一支 GAS 自己個 Script Properties，
  冇第二個系統識得到**——所以閂呢支淨係影響呢支，天然唔會「波及其他團」。
- 呢個 flag 有兩條寫入路，兩條都係 vsbadge 白名單認可、唔需要求人：
  1. **下游自己在 Sheets 選單閂**（`menuLocalLoginOff` → 直接改 flag）；
  2. **上游打 `setLocalLogin`**——vsbadge `callDownstream(downstreamId,'setLocalLogin',{allow:'false'})`
     用下游 SHEET KEY 簽名直打落去。`setLocalLogin` 喺簽名寫入白名單
     （`LINK_SIG_WRITE_ACTIONS`），唔鍾意簽名就閂唔到。
- 授權 = **邊個執住嚟條 SHEET KEY（＝API_KEY）**。sig 公式
  `HMAC-SHA256("vsbadge-troop-sig-v1", SHEET_KEY)`，冇 key 就出唔到有效簽名，
  後端 `verifyLinkSig` 一定打返轉頭。呢個正正係你講嘅「用戶接 URL＋API KEY」。
- VS-PORTAL（呢邊）**毋須喺 VSBADGE 個前端做任何協調**：vsbadge 前端
  `index.html` 根本冇「閂門」掣；關門係後端對後端嘅事。VS-PORTAL 要做嘅係：
  響 Vercel（`TROOP_<編號>_APIKEY`）keep 住嗰條 SHEET KEY，再芯加多個 action
  （`getLinkState` 讀門況 ＋ `setLocalLogin` 閂／開）就夠。Vercel seed 用 key 出簽名，
  唔使掂本地 storage；而呢邊已有嘅 `signedPost()` 就係現成簽名料。

> 一句講晒：唔使郁 VSBADGE 前端。關門 = 有 key 嗰個（Vercel VS-PORTAL）用簽名
> 打 `setLocalLogin` 過去，淨係嗰支後端個 flag 轉 `false`，其他團連知都唔知。

**② VS-PORTAL 自己支後端（Code.gs / gastemplate.js）加同款「直接入口」掣：**

### ⑦ 求救制 —— 有咩大問題 SEND 去 ADMIN，當回報問題處理

團長：「我唔想怕防鎖死，反而想加個求救制，有咩大問題就 SEND 去問 ADMIN，當回報問題處理。」
後補：「（ADMIN）佢因為配合圖書館嘅問題回報所以有呢樣紀錄。」

即係 ADMIN 本身已經有一張**「問題回報」TICK 看板**（圖書館嗰個 `report.html?app=圖書館`、
Scout Admin 後台「🐛 問題回報」分頁都係同一張表）。呢個求救制**唔係新造一套**，
而係把 VS-PORTAL 份報告**照 Scout Admin「問題回報」合約**塞入同一張表：

走**「開戶申請」同一條路**（唔係新造一條）：

- **個掣喺頂部狀態列**（任何一版都見到）＋「總表同步」頁都有一粒，撳開彈框填：**標題＋嚴重度＋問題詳情**。
- **未登入都用得**（呢個先係個制嘅重點）：登入畫面、未能連線嘅後端閘、未揀旅團嘅揀選閘都有粒「求救／回報問題」掣。
  未登入嗰陣要填返「你個名（可選）＋ Email（必填，ADMIN 轉寄跟進用）」；登入咗就自動帶身份＋Email。
- **團員入口（members.html）都有粒「求救」**：登入閘（未登入）＋登入後頂欄都放；團員報告同管理系統用同一條 `openMemberSOS → validateIssue → submitIssue`，
  照樣落入 ADMIN「問題回報」表，帶埋嗰位團員個名＋（名冊有嘅話）Email。團員自己填嘅 Email 無效嗰陣唔會靜靜放行。
- 送出：`validateIssue → submitIssue → 同源 proxy submitIssue → 中央 ADMIN 收件匣`
  （`SCOUT_ADMIN_API`，同 VSBADGE／圖書館共用）。
- 送出之前先落**本機求救紀錄**（`db.issueReports`，跟「儲存到後端」一齊上後端、
  換機都留得返）；送唔到嗰陣照舊有「複製報告內容／再試」掉返手（同開戶一樣）。

**ADMIN 收件匣（Scout Admin GAS）對正佢自己嘅 `doPost` 合約** —— 唔使佢加任何嘢，
佢一收到 `type:'issue'` 就自己寫入「問題回報」工作表（Email 附全部欄位＋原始 JSON 備份）：

```
POST { type:'issue', sourceApp:'82venture', title, desc,
       severity:'低|中|高|緊急', troopId, name, contact }
```

- ADMIN GAS `doPost` 只認 `type === "issue"` 先落「問題回報」表（其他 type 會落「申請記錄」）。
- 「問題回報」表欄位：提交時間／來源 APP／旅團號／標題／問題詳情／嚴重度／聯絡方式／姓名／狀態／編號。
- 收件匣**唔回執真回執**：admin GAS 回 `{ status:'success'|'error' }`，proxy 見 `status:'error'`
  先當失敗；照舊 POST 過得去就當送到（同開戶一樣）。

**寫入路冇變**：求救紀錄自己唔會自動寫後端，照舊跟頂部唯一嗰粒「儲存到後端」，
`saveTables/loadTables` 係按表名通用存，所以 `issueReports` 自動上落，不用改 Code.gs。
