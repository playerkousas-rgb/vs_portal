## A. 關鍵 bug：「開新通告」掣撳落去冇反應

**症狀**（團長回報）：通告頁撳「開新通告」完全冇反應 —— 要手動改網址 `#/notices/new` 先入到編輯器。

**原因**：`assets/js/views/notices.js` 嘅 `mount()` 入面，**詳情頁動作** handler 綁定咗所有 `[data-act]`，
但係冇 `act === 'new'` 呢個分支；`data-act="new"` 呢粒掣（頁頭＋列表各有一粒）因此冇任何 listener。

**為咩測試一直捉唔到**：`tests/smoke.mjs` 開編輯器嗰陣係直接 `window.location.hash = '#/notices/new'`，
即係繞過咗 mount() 嘅事件綁定 —— 掣壞咗都照樣「通過」。

**改法**：

```js
// assets/js/views/notices.js — mount() 詳情頁動作 handler 最前面
if (act === 'new') { draft = null; draftPhotos = { photos: [] }; return go('#/notices/new'); }
```

（跟 `views/members.js` 嘅寫法；同時清走上一次嘅草稿同相片，避免新通告帶入舊內容。
要放喺 `const n = find('notices', params.id)` **之前**，因為列表頁嘅 `params.id` 唔係通告 id。）

**測試**（`tests/smoke.mjs`，新）：**撳真嗰粒掣** → 驗 `hash === '#/notices/new'`、編輯器有 `#n-title`、
標題欄係空白（唔會帶入上一張），之後返列表繼續其他測試。

## B. 公開頁讀唔到 app 新開嘅通告（報名測唔到）

**症狀**：`0082` 喺 app 開新通告、發布咗，公開頁（`notice.html?u=0082&n=…`）永遠讀唔到 → 報名流程測唔到。

**原因**：`assets/js/public-notice.js` 原本係「**靜態** `data/units/<編號>/notices.json` **完全冇嘢**先讀旅團後端」。
0082 有靜態通告檔（2 張種子通告），所以後端（旅團自己 Sheet 嘅「通告全文」分頁）**永遠唔會讀**。

**改法**：改為**合併**，同 `id` 以**後端為準**：

```js
const backendList = await fetchBackendNotices();
if (backendList.length) {
  const m = new Map();
  list.forEach(n => m.set(String(n.id), n));
  backendList.forEach(n => m.set(String(n.id), n));   // 同 id：後端覆蓋靜態
  list = [...m.values()];
}
```

效果：① 靜態有、後端冇 → 照舊睇到；② app 新開（只喺後端）→ 睇到；③ 同 id 兩邊都有 → 以後端（團長最新版本）為準，唔會重複。

**測試**（`tests/public.mjs`，新 case ②c）：以 0082（有靜態檔）＋ stub 後端驗證以上三種情況。

## C. 新功能：已發布通告詳情頁「同步到公開頁」

公開頁讀嘅係**旅團自己 Sheet 嘅「通告全文」分頁**，所以開新／改完通告要經總表同步先出到公開頁。
以前要去「帳號與系統 → 資料管理 → 總表同步 → 立即同步全部」，團長唔會記得。

**改法**：詳情頁（已發布 ＋ 有 `table.sync` 權限）分享卡加一粒 `data-act="sync-notice"`：

```js
const tables = await import('./tables.js');
const r = await tables.pushToMaster({ silent: true });
// 成功：toast「已同步到公開頁 —— 通告全文已更新」
// 失敗：toast「同步失敗：…（如失敗，請去「帳號與系統 → 資料管理 → 總表同步」檢查 /exec 網址同 API Key）」
```

同步中會把掣轉做「同步中…」並停用，完成後還原（可以再撳）。成功／失敗**都會 toast**，唔會靜靜地冇反應。

**測試**（`tests/smoke.mjs`，新 section「通告詳情頁（同步到公開頁）」）：撳真掣 → 驗 POST `action=sync`、
payload 有 `tables.notices`（含嗰張通告）、帶旅團編號＋API Key、成功 toast、掣還原；
再測失敗路徑（`/exec` 回 500）→ 要有 toast，而且提示去「總表同步」檢查 `/exec` 同 API Key。

## 端到端實測（真 HTTP，22 通過 / 0 失敗）

用 `node dev-server.mjs` 起真伺服器（PORT=8010），前端所有請求都係真 HTTP；
**唯一代替品**係旅團 Google Apps Script —— 呢個環境冇外網
（`curl https://script.google.com` → `SSL_ERROR_SYSCALL`，HTTP 000），
所以用本地 stub 企代（行為跟 `Code.gs`：`sync` 寫入表格、`notices` 回通告全文、`noticeSignup` 寫報名），
並以 `V82_PROXY_TEST=1` ＋ `TROOP_0082_BACKEND=http://127.0.0.1:9099/exec` 令 `/api/proxy` 指向 stub。

| 段 | 結果 |
| --- | --- |
| ① 撳「開新通告」（修復 A） | 有反應 → 跳 `#/notices/new` → 編輯器開到 |
| ② 填「實測：秋季露營報名（E2E）」→ 發布 | `status=published`、報名欄位齊（姓名／電話／出席與否）、跳去詳情頁 |
| ③ 詳情頁撳「同步到公開頁」（修復 C） | 後端收到 1 次 `action=sync`，內容包埋呢張新通告；toast 成功 |
| ④ 公開頁 `notice.html?u=0082&n=…`（修復 B） | 睇到新通告＋活動詳情（地點／費用／名額）；未填必填會擋住；填好送出 → 後端「報名」收到 1 份（姓名／電話／出席＝出席、對應通告編號）；本機都留低一份暫存 |

> 即係：**app 開通告 → 同步 → 公開頁報名 → 後端收到**，成條鏈路通。
> 唯一未喺呢度驗證嘅係「真 Google Sheet 寫入」呢一跳（要團長喺自己瀏覽器撳一次「同步到公開頁」，
> 再開公開頁確認）。
