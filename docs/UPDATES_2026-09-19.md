## 一、兇手：兩條路得一條行得通，而正路唔係你自己搞得掂嘅

系統由頭到尾有**兩條**去後端嘅路：

| 路 | 點接線 | 邊個做得到 |
|---|---|---|
| ① 同源 `/api/proxy`（正路） | 平台管理員喺 Vercel 加 `TROOP_0082_BACKEND` ＋ `TROOP_0082_APIKEY` | **只有平台管理員** |
| ② 直接打你自己嘅 `/exec` | 你喺「總表同步 → 同步設定」貼 `/exec` ＋ API Key | **你自己** |

`assets/js/lib/remote.js` 舊嘅 `callBackend()` 係咁寫：

```js
const r = await postJson('api/proxy', body, timeoutMs);
if (r.ok && r.json) return normalize(r.json);
/* proxy 唔存在（純靜態部署）→ 跌落去直接打 /exec；其他錯誤照報 */
if (!r.noApi) {
  if (r.json) return normalize(r.json);      // ← 兇手喺呢行
  if (r.error) return { ok: false, ... };
}
// ② 直接打 /exec —— 只有 r.noApi 先至行到呢度
```

而 `api/proxy.js` 對「未登記旅團」回嘅係 **HTTP 404 ＋ 一個 JSON**：

```json
{ "success": false, "error": "找不到此旅團或後端網址未設定" }
```

`postJson()` 只在**回應唔係 JSON** 嗰陣先至 set `noApi`。所以：

* `r.json` 永遠 truthy → 函數喺 ① 就 `return` 咗；
* **② 條路一行都未行過** —— 你貼嘅 `/exec` 形同虛設。

### 後果（＝你見到嘅症狀）

| 你見到 | 實際發生 |
|---|---|
| 無痕＋普通 Chrome 都同步唔到 | 兩邊都經 ①，① 回 404，② 行唔到 → 讀寫全部死 |
| 貼咗 `/exec` 都係唔得 | 同上：貼咗都唔會用 |
| 公開連結（團章／通告／記帳／借用）冇修好 | 公開頁**淨係**打 `api/proxy`，404 就當「未發布」 |
| 「總表同步」話「未設定後端」，搵唔到掣 | 見下面第二節 |
| 之前幾次更新「好似修咗但冇效」 | 修嘅係 ① 條路（樂觀鎖、版本對比、focus 即拉）—— 全部正確，但 ① 根本未通，所以乜都感覺唔到 |

### 重現證據（改之前，本機真 HTTP 跑）

```
=== A. 乜都未填（平台環境變數未登記）===
remoteInfo(): {"ok":false,"error":"找不到此旅團或後端網址未設定"}
pushDb()   : {"ok":false,"error":"找不到此旅團或後端網址未設定"}

=== C. 對照：直接 curl 同一個 /exec（證明後端本身正常）===
```

## 二、第二個封鎖：「總表同步」頁把逃生門一齊收埋

`syncView()` 用 `backend ? … : …` 閘住成張「儲存狀態」卡：

```js
const backend = load().backend || null;
${backend ? `…立即儲存到後端 / 由後端還原資料 / 睇後端有咩資料 / 體積檢查…`
          : `<b>未設定後端 —— 你嘅資料而家淨係存喺呢部機嘅瀏覽器。</b>`}
```

但 `db.backend` 只喺 `seedBackend()` 攞到 `backendOf(code).gasUrl` 嗰陣先會 set，
而 `backendOf()` 讀嘅係**前端** Registry（`data/units.json`／`/api/units`／焗名單）——
呢三個基於安全**永遠唔會帶 gasUrl**（`listPublicUnits()` 明確只回公開欄位）。

所以**凡係用 Vercel 環境變數登記嘅旅團（即係正路做法），`db.backend` 一定係 `null`**：

* 個頁永遠話「未設定後端」；
* 「立即儲存到後端」「由後端還原資料」「睇後端有咩資料」「體積檢查」「相片瘦身」全部收埋；
* 而 `docs/FIX_API_KEY_2026-09-17.md` 同 `docs/UPDATES_2026-09-18.md` 一再叫你
  「去總表同步撳『立即儲存到後端』」「撳『由後端還原』」—— **嗰啲掣你根本撳唔到。**

呢個先係字面意義上嘅「把解決問題的方式封掉」。

## 三、修咗啲乜

### 1. 新增 `assets/js/lib/gateway.js` —— 兩條路統一，兩條都要行得通

* `postBackend(payload, { unit, execUrl, apiKey })`：先試 ①，
  **proxy 話「未登記呢個旅團」就跌落 ②**（以前呢度直接收工）。
* proxy 回**其他**錯誤（未授權／後端壞／逾時）→ 照舊如實報，唔會扮冇事。
* `isExecUrl()`：你自己貼嘅 `/exec` 一定要係

* `callBackend()` 改用 `postBackend()`；回傳多咗 `via`（`'proxy'`／`'direct'`），
  界面同診斷可以講清楚「今次行緊邊條路」。

  （唔再係一句「找不到此旅團」）。

* `remoteInfo()` 問唔到後端會 set 新狀態 `unreachable` ——
  以前靜靜雞回，右上角照樣顯示「已連後端」，你完全唔知其實一直冇同步。

  | 自己貼嘅 `/exec` | 格式啱唔啱、有冇附 key |

## 一、死因：開機讀唔到後端，就當冇事，跟住照樣寫

`assets/js/main.js` 嘅開機流程係咁寫嘅：

```js
try {

  …拉返最新…

remoteApi.arm();                                // ← 照樣開自動儲存
```

而 `arm()` 入面係：

```js
export function arm() {
  armed = true;
  if (hasPending()) scheduleSave();   // ← 見到有未存改動，2.5 秒後就 push
}
```

所以只要開機嗰下 `remoteInfo()` 失敗 —— GAS 凍啟動逾時（成日 30–45 秒）、網絡
抖一下、平台 proxy 一時 5xx —— 個 `catch` 就靜靜雞食咗佢，然後 `arm()` 即刻把
本機積落嘅改動推上後端。**未讀後端就已經寫後端。**

兩部機輪流開，就係你講嘅「永遠自己睇自己」。

### 舊有嘅保護，點解全部堵唔到

|---|---|
| 空機保險閘 `blank_guard` | 只擋「本機完全冇內容」嘅**新機**。一部用咗好耐嘅機（有內容、`lastSyncedVersion` 係舊值）完全唔受保護 —— 而呢個先係你哋日常嘅情況 |

```

```

**正確做法**：要分得到「本機**真係改過**」同「本機淨係有一份舊／種子副本」。
所以記低一個**基準指紋**（`sync.baseObjHash`）—— 呢部機上次同後端對齊嗰陣，
每個物件欄位嘅內容指紋。合併嗰陣：

| 情況 | 判斷 | 結果 |
|---|---|---|
| 冇 base（從未對齊過） | 手上嘅唔算改動，只係舊副本 | **後端贏** |
| `hash(本機) === base` | 本機冇改過 | **後端贏**（後端新嘢照入） |
| `hash(本機) !== base` | 本機真係改過 | **深層合併，衝突嗰格本機贏** |

基準喺三個位更新：**種子建立時**（`init()`）、**拉後端後**（`adoptRemote()`）、
**push 成功後**（`markBaseAligned()`，而且淨係喺冇剩低未同步改動嗰陣）。

「種子建立時就要有 base」呢一點好關鍵：如果等第一次同步先至記，
一部全新機「開機 → 填 IG／FB → 撳同步」就會因為未有 base 而被當成「冇改過」，
填嘅嘢又被蓋返 —— 正正係你回報嘅情況。
