## ② 「資料入到資料庫，但分頁冇放好／新儲嘅完全讀唔到」——後端 v2.7.0

### 死因 A：讀取（新儲嘅讀唔到）

「資料庫」分頁每一行係一段 JSON（一個旅團嘅資料可能分幾十段，每行都帶住寫入時嘅**版本**）。
舊版讀法係「同一個旅團所有段**一齊拼**」——只要分頁入面出現兩套以上嘅段
（舊版漏刪、有人手動加行、兩個部署同時寫），就會：

* 拼出嚟嘅 JSON **parse 唔到** ＝ 完全讀唔到；或者
* 舊一套嘅段排喺前面 → **永遠只讀到之前儲嗰份**，新儲嘅好似消失咗。

而家：`dbRawText(unit)` **按版本分組**，由新到舊逐套試 parse，**只回最新一套完整**嘅段；
舊段一行都唔會混入。回應同時帶 `versions`／`staleRows`／`brokenNewer`，方便診斷。

### 死因 B：寫入（永遠儲存唔到）

`saveDb`／`saveDbCommit` 嘅樂觀鎖要對 `baseVersion`。舊版寫入路攞「**最後一行**」嘅版本 ——
如果最後一套寫到一半（半截 JSON，parse 唔到），讀取路會回**上一個完整版本**，
但寫入路攞住嗰個壞版本 → `baseVersion` **永遠對唔上** → 每次都回
「後端已有較新版本（另一部機剛剛同步過）」→ **即係永遠儲存唔到**。

而家兩個路徑用同一套判斷：寫入路用 `dbRawText(unit, true).version`
（strict 模式只認同一個旅團）；讀到嘅同寫入核對嘅一定係同一套。

### 分頁（人睇得明嗰啲）

v2.6.3 起：**一次「儲存到後端」由後端自己寫齊**「資料庫」分頁＋團員／帳目／物資／通告／會議…
報表分頁（`refreshReportsFromDb()`），回應帶 `reports` 講明寫咗咩／寫唔到咩。
所以正常情況下唔會再出現「資料入咗，但分頁空空如也」。

### 逃生門（一次性，喺 Apps Script 執行）

| 函數 | 幾時用 |
|---|---|
| `cleanStaleStaging()` | 「資料庫」分頁塞咗舊版留低嘅 `__staging__` 垃圾行（分頁越嚟越大、變慢） |
| `pruneOldDbVersions()` | 同一旅團有**兩套以上版本段**（永遠只讀到舊嗰套）—— 只刪舊段，最新一套唔會掂 |

兩個都回 `{ok, removed, rowsLeft}`，並喺 `Logger.log` 交代清走幾行、剩返幾行。

### 測試（新釘死）

* `tests/gas.mjs` 新增 **③b（★ v2.7.0）**：兩套版本 → 只讀最新、舊段唔混入 → `dbInfo.staleRows`／`versions` →
  `pruneOldDbVersions()` → 最新一套完好 → 最新一套**寫壞**（半截 JSON）→ 自動回退上一個完整版本（`brokenNewer`）→
  之後 `saveDb` 用**讀到嘅版本**照樣存得入 → 存完只剩一套版本。
* `tests/remote.mjs`：`dbRawText(unit, strict)` 簽名 ＋ 兩條寫入路都係 `dbRawText(unit, true).version`。

## ④ 團長：每團一位 · 第一個開戶嗰位 · 只可以轉移

* **第一個開戶嗰位就係團長**：用開團 KEY（`issueSetupKey()` 72 小時）或者首位登入嘅人，
  入到去即刻被問「認領團長身份」（`canClaimChief()`／`claimChief()`，可以撳「稍後」）。
* **永遠只有一位**：`model.chief()` 全旅團搵一位；轉移時舊團長自動變返**領袖**
  （`transferChief()`，審計紀錄「轉移團長身份」）。
* **只可以轉移**：團長身份**唔可以**喺身份下拉直接改低；亦**唔可以自己改自己**（防止鎖死）；
  只有現任團長／超管有 `admin.chief`。
* **權限**：團長 = 領袖全部權限 ＋ `admin.chief`（轉移團長）＋ 改任何非超管密碼。
* 舊資料升級（`guessIdentity()`）**永遠唔會自動產生首席** —— 舊「團長」職位一律先當領袖，
  否則一升級就會變出幾個團長。

## ⑥ 進度對接：要唔要喺 Vercel VSBADGE 加 `PORTAL_DEFAULT_ORIGIN`？

**答：唔需要。**（唯一例外：如果你想用「免登入 portal 入口」，見下面「例外」。）

### 點解

我哋而家行嘅係「**一個後端、兩個前端**」（2026-09-16 定案）：

```
深資童軍管理系統（前端）──┐
                        ├──▶  旅團自己嘅 Google Sheet ＋ 一支 Apps Script（/exec）
進度前端（vsbadge）    ──┘
```

兩個前端**讀寫同一份資料**，靠嘅係 **`/exec` 網址 ＋ API Key**，唔係 origin 對接：

* `/exec`（Apps Script）**冇 CORS／origin 檢查**，請求係由 vs_portal 嘅伺服器端 `/api/progress` 發出
  （同源、API Key 唔會出現在網址或 log）。
* VSBADGE 嘅 `PORTAL_DEFAULT_ORIGIN`（＋`PORTAL_DEFAULT_ROLES`）係**另一件事**：
  佢係舊「portal 對接」嘅來源白名單 —— 主系統送用戶去
  `vsbadge.vercel.app/?u=…&role=…&from=portal&src=https://主系統` 免登入入去用，
  vsbadge 要核對 `Referer`／`src` 對得上 `portalOrigin`（fail closed，冇設＝全部旅團唔開放 portal；
  一設就**所有已登記旅團**都開放，角色另受白名單限制）。

### 喺 vs_portal 點登記（你已經做咗嘅嗰步）

1. 喺進度前端（vsbadge）嘅 Sheet 選單撳「🔑 顯示 API Key」複製 **API Key**，同埋抄低 Apps Script 嘅 **`/exec`** 網址；
2. 喺深資童軍管理系統「**進度 → 設定**」貼上去 →「測試連線」；
   （或者：伺服器端設定 Vercel 環境變數 `TROOP_<旅團編號>_PROGRESSBACKEND` ＋ `TROOP_<旅團編號>_PROGRESSAPIKEY`
   —— 甚至只用本來已有嘅 `TROOP_<編號>_BACKEND`／`_APIKEY`，系統會自動沿用同一個 `/exec`；
   設咗就唔使喺前端填，API Key 亦唔會落瀏覽器。）
3. VSBADGE 嗰邊**唔使加任何環境變數**。

### 例外／注意

* **想由系統開一條「免登入跳去 vsbadge」嘅連結** → 先要喺 VSBADGE 設
  `PORTAL_DEFAULT_ORIGIN = https://<你 vs_portal 嘅網址>`（＋`PORTAL_DEFAULT_ROLES`），
  而且個 role 要在該旅團白名單。2026-09-16 已經決定**唔用呢條路**（改為直接接駁），所以正常唔需要。
* **旅團如果「閂咗本機直接入口」**（旅系統升級嘅 `ALLOW_LOCAL_LOGIN=0`），API Key 都會被拒
  （該節點只收上游 `sig`）→ 要接通進度就先開返直接入口，或者登記上游。
* vs_portal 自己嘅 `api/portal.js`／`PORTAL_SESSION_SECRET`／`TROOP_<id>_PORTALORIGIN` 係**另一件事**
  （上游旅系統 → 支部入口），同進度對接無關。

## ⑦ 進度讀唔到？（「人係讀到、但個個都冇進度」＋ 無痕讀唔到後端）

### 症狀對照

| 你見到嘅 | 真正原因 | 點做 |
|---|---|---|
| 無痕（或者另一部機）「讀唔到後端」 | 進度設定（`/exec` ＋ API Key）係**跟旅團資料庫走**嘅，但你未撳頂部「**儲存到後端（N）**」→ 只有填嗰部機有 | 喺填好設定嗰部機撳「儲存到後端」；跟住任何裝置（包括無痕）登入後就自動有 |
| 入咗 URL ＋ API Key，「測試連線」見到**有成員**，但「總覽」全部 0 | 後端嘅「**進度追蹤**」分頁係空／唔見咗，或者你填嘅 `/exec` 唔係進度資料嗰張 Sheet | 撳「**後端資料檢查**」（見下）跟住做 |
| 有進度但每個人顯示 0 | 「進度追蹤」第一欄嘅 **YMIS** 同「成員名單」唔一致 | 對 YMIS；去「用戶名冊」補／改 |

### 新功能：進度 → 設定 →「後端資料檢查」（★ v2.7.1）

一粒掣問後端三件事（`GET ?action=diag`，要 API Key；前端經同源 `/api/progress`）：

1. **邊張 Sheet**：`GET /exec`（唔使 Key）自報 —— 試算表名、後端版本（`v2.7.1`）；
   唔認得 `diag` ＝ 呢支腳本唔係管理系統嘅後端（舊版／另一支）。
2. **分頁同行數**：`資料庫`／`團員`／`成員名單`／`進度追蹤`／`其他獎章`／`待批完成`／
   `活動履歷`／`待批履歷` 各幾多行；缺咗嘅列晒出嚟（`missingTabs`）。
3. **對唔對得上**：`進度追蹤` 有幾個 YMIS／項目，其中幾多個喺「成員名單」度（`matchedWithMemberList`）。

跟住 app 直接出結論同步驟，例如：

* 「『第82旅總表』嘅『進度追蹤』分頁一條紀錄都冇」→ 教你睇分頁係唔係唔見咗；
  唔見咗就喺 Apps Script 執行 `initializeSheets()`（只補缺，唔會刪資料）；
  如果係啱啱唔見，**Google Sheets「檔案 → 版本記錄」可以還原舊版（連分頁資料）**；
  如果資料其實喺另一張 Sheet（進度前端嗰張）→ 去「設定」改用嗰支 `/exec` ＋ API Key。
* 「有進度紀錄，但冇一個 YMIS 對得上成員名單」→ 教你對 YMIS。
* 「呢支 `/exec` 唔係管理系統嘅後端」→ 交代兩種可能同做法。

`load`（進度資料）本來就會把「後端成員數 vs 有進度嘅人數」報上嚟，所以總覽亦會喺
「有成員、零進度」時自動彈一張橫額叫你去檢查（唔會靜靜地顯示全部 0）。

## ⑧ 「資料綁死喺我部機，其他人登入睇唔見」——後端 v2.7.2 搶救三寶

> 團長同日第三輪：「資料現在還是綁死在我本機瀏覽器內，其他人登入根本看不見。」
> 以下先講**點解會咁**、再講**喺 app 內點救**（唔使入 Apps Script）。

### 設計上，資料一路都係後端做正本

流程係：登入 → 由 `/exec` 讀返成個旅團嘅「資料庫」→ 畫面用嗰份；瀏覽器 `localStorage`
只係**快取＋離線後備**。所以只要後端通、`/exec` 指得對，換機／無痕／第二個人登入
都會見到同一份。真係「綁死一部機」，一定係下面其中一種（app 而家會直接講出係邊種）：

| 你見到嘅 | 真正原因 | 邊件工具醫 |
|---|---|---|
| 我部機有齊資料，其他人／無痕一片空白 | 後端「資料庫」分頁**讀唔到**（同一旅團有兩套版本段／寫到一半嘅壞行）—— 有快取嗰部機照開門，冇快取嘅（無痕、新同事）就空空如也 | ② 修復後端 |
| 每部機各自有一份，永遠夾唔埋 | `/exec` 指咗去**第二支腳本／第二張 Sheet**（或環境變數未設），大家其實寫緊唔同嘅 Sheet | ① 檢查後端（會講出邊支腳本、邊張 Sheet） |
| 後端係舊嘅／空白，我部機先係最新 | 後端一直冇收到你份資料，一路靠本機快取頂住 | ③ 用呢部機嘅資料上載 |

### 搶救三寶（app 內，撳掣）

**入口兩個，同一組掣：** 登入閘（連唔到後端時會自己彈）＋「資料管理 → 儲存狀態」卡。

| 步驟 | 掣 | 做咩 | 會答你咩 |
|---|---|---|---|
| ① | **檢查後端** | `status` → `dbInfo` → 試讀一次 | 連住邊支腳本、邊張 Sheet、版本號、幾多位成員、有幾套版本段、幾行暫存垃圾、判定「正常／**讀得到但分頁有垃圾（趁未壞快手清）**／似唔係本系統／讀唔到」＋下一步 |
| ② | **修復後端** | 後端 `repairDb`：清 `__staging__` 垃圾行、刪**舊**版本段 | 清走幾行、保留邊套版本、修完讀唔讀得返、仲有幾多位成員 |
| ③ | **用呢部機嘅資料上載** | 後端 `saveDbForce`：**跳過版本鎖**，用你部機份資料做正本 | 覆蓋咗邊個舊版本（`overwroteVersion`），跟手自動重寫所有報表分頁 |

③ 要**打字確認**（要你打「上載」兩個字）先會做，而且只喺「本機有資料、後端讀唔到」時至會出現
（`canForce`）——即係唔會有人手快快覆蓋咗一份好嘅後端。做錯都有得返轉頭：版本記錄仲喺
「資料庫」分頁，App 內「版本記錄」頁睇得到。

### 後端 v2.7.2：`repairDb` 同 `saveDbForce`

* `repairDb`（要 API Key）→ `{ok, unit, before, removedStaging, removedOldVersions, keptVersions, skippedUnits, after, loadOk, members}`
* `saveDbForce` ＝ `saveDb` 帶 `force:true` → 跳過 `baseVersion` 鎖，回應多 `forced:true`／`overwroteVersion`；
  **普通儲存照樣有版本鎖**（兩部機同時改仍然會撞，唔會靜靜地蓋過）
* `pruneOldDbVersions()` **重寫**：由 v2.7.0 嘅「按時間留最新」→ 改為「留**最新一套砌得返 JSON** 嘅段」。
  點解要改：舊寫法遇着「最新嗰套係壞嘅」，會親手刪走**唯一一套好資料**；而家
  全部套都壞 → **一行都唔刪**，回報 `skippedUnits` 等人手處理。冇版本欄嘅遠古行一樣永不刪。

### 為何同 VSBADGE 一樣「唔複雜」

團長叫我參考 VSBADGE（簡單系統）：其實兩套都係「一個後端（Apps Script＋Sheet）＝正本」

### ④ 「1 邊能用 email 登入、1 邊不能」—— 真正嘅死因同修法

**死因（已用測試重現）**：「身份即帳號」之後，名冊紀錄本身就係登入帳戶，
但 `setMemberHubPassword()`／`add('members')` 全部都係 `commit()` →
**只寫 `localStorage` ＋ `pending +1`**，後端一個字都未收到。
另一部機開機行 `requireBackendForLogin()` → 由後端拉 → 後端冇呢個人 → 「電郵／YMIS 或密碼不正確」。
超管行 `api/auth.js`（伺服器端核對 `SUPER_KEY`），**完全唔經旅團後端**，所以淨係佢永遠入到 ——
團長嘅判斷一句都冇錯。

**修法（三層）**：

1. **帳戶級寫入即刻寫後端** — `store.js` 新增 `IDENTITY_COLLECTIONS`
   （`members`／`accounts`／`accountApps`）＋ `commitCritical()`；
   `add`／`update`／`remove` 寫呢三個 collection 就當帳戶級。
   `auth.js` 十處 `commit()` 全部改 `commitCritical()`。
2. **自動寫入** — `remote.scheduleSave({critical})`：一般改動 debounce `AUTO_SAVE_DELAY_MS`（1.2 秒），
   帳戶級改動 **0ms 即刻寫**。寫入依然係**同一條路** `saveToBackend`
   （核對版本 → 三方比對 → 撞就問），所以唔會有「兩條路互相蓋」。
   可以在「總表同步」關（`setAutoSave(false)`，跟旅團資料存）；
   團員入口（`members.html`）用 `suppressAutoSave(true)` —— 團員交嘢照行 `pushSubmit()`。
3. **跨視窗同步** — `store.bindCrossTabSync()`（喺 `store.init()` 綁，所有入口都有）：
   聽瀏覽器 `storage` event（**只有其他分頁**寫先會派）→ `mergeFromOtherTab()` 用同一套
   三方比對併入 → 派 `v82:external` → 介面重畫。另外 `visibilitychange` 切返分頁會
   `refreshIfClean()`（本機冇未存改動先至拉，唔會彈衝突框）。

**順手修嘅真 bug**：
* `saveToBackend()` 撞正背景寫入會回 `{reason:'busy'}` → 用家見到「儲存失敗」。
  而家所有儲存排成一條隊（`saveChain`），等前一次完成先至行。
* `dev-server.mjs` 從來冇讀 request body → `api/auth.js` 喺 `npm run dev` **一定**回
  「請求格式錯誤」（超管本機登唔到，同 Vercel 行為唔一致）。已補 `readReqBody()`。

### ⑩-1 寫入後端只有一個掣（團長第 1、2、11 點）

#### 團長點解要咁

> 「我只想要頂部1個儲到後端的制,其他任何時候都是暫儲在遊覽器」

2026-09-24 第四輪我為咗救「帳戶寫唔入後端」加咗**自動寫入**（一般 1.2 秒 debounce、帳戶級 0ms）。
團長明確否決。原因好簡單：**有自動寫入，用家就唔會知道系統幾時寫咗、寫咗乜**，
而「頂部嗰粒掣」亦都變得語意模糊（係「即刻寫」定「唯一寫」？）。

#### 我問咗乜，團長答咗乜

> 我：「點解唔即寫就唔得？只係要寫入後先可以，還是之後寫入後端都不可以？」
> 團長：「（反問）」

**答案：之後寫完全冇問題。** 技術上冇任何機制要求即刻寫。
死因唔係「時間」，係「根本冇人寫」：

```js
// requireBackendForLogin() —— 登入核對讀嘅係**後端**嗰份名冊
const r = await loadFromBackend();          // ← 由 Google Sheet 拉
const acc = (tryLoad()?.accounts || [])…    // ← 用拉返嚟嗰份核對密碼
```

A 機開完人，只要**喺 B 機嘗試登入之前**寫入後端就得。之前壞，係因為冇任何機制迫你寫、亦冇提醒。

#### 改法

拆走成條自動寫入路（全部喺 `assets/js/lib/remote.js`）：

| 拆走 | 舊作用 |
|---|---|
| `async function autoSave()` | 背景寫入 |
| `AUTO_SAVE_DELAY_MS` / `autoTimer` | 1.2 秒 debounce |
| `autoSaveHalted` | 「未由後端載入過」暫停旗 |
| `export function setAutoSave()` / `autoSaveOn()` | 開關（跟旅團資料存） |
| `export function flushAutoSave()` | 即時 flush |
| `suppressAutoSave()` | 團員入口閂自動寫入 |
| `setAutoConflictResolver()` | 自動寫入撞格時嘅確認框 |

`scheduleSave()` 而家淨係 `setState('pending', …)`，**一行寫入都冇**。

#### 咁「帳戶寫唔入後端」點算？→ 鬧醒，唔係代勞

`sync.pendingAccounts` **另外計數**（`store.js` 嘅 `commit()` 見到 `critical` 就 +1）：

```
未寫入後端：3 項（包括 2 個帳戶改動 —— 未寫入，佢哋喺其他裝置登唔到）
```

頂部 chip 只要有帳戶未寫入就**轉紅**（`b-danger`）並寫「N 個帳戶未寫入後端」；
登入頁橫額亦會紅色警告；登出／閂頁會擋住問。

> ⚠️ **代價（要講清楚）**：而家如果團長開完人**唔撳**頂部掣就收工，
> 嗰個人喺第二部機依然登唔到 —— 同 2026-09-24 之前一樣。
> 分別係**而家會鬧醒佢**（紅字 ＋ 登出擋住），唔會靜靜地漏。
> 如果團長之後覺得鬧唔夠，可以再加「登出前自動寫一次」（要佢点头先做）。
