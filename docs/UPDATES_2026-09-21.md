## ① 「話佢無後端」—— 真死因：旅團編號打「82」，但登記嘅係「0082」

團長喺**旅團選擇畫面**有個「輸入旅團編號」格（`#gateCode`）。第八十二旅最自然嘅打法係「82」
（個 logo 都係顯示 `82`，`main.js` 仲特登 `String(u.code).replace(/^0+/,'')` 攞走前導零嚟顯示）。
但 Registry 嘅 key 係「**0082**」（環境變數 `TROOP_0082_BACKEND`）。

中間層兩邊都只試『原樣』同『搣走前導零』兩種寫法 —— **永遠砌唔出「0082」**：

| 位置 | 舊行為 | 後果 |
|---|---|---|
| `api/_registry.js` `getTrustedUnit('82')` | `reg['82'] \|\| reg['82']` → `undefined` | `/api/proxy` 回 **404「找不到此旅團或後端網址未設定」** |
| `assets/js/lib/units.js` `unitEntry('82')` | `all['82'] \|\| all['82']` → `null` | 「同步設定」畫「未設定後端」 |
| `assets/js/main.js` `gotoUnit()` | 原樣 `?u=82` ＋ `db.unitCode='82'` | 登入硬閘 → 「**未能連接旅團後端**」＝用家見到嘅「無後端」 |

所以「無後端」係**假警報**：後端登記得好哋（`/api/units?diag=1` 一直回 `backendReady:true`），
只係少咗兩個 0。而且呢個唔止擋住讀 —— 擋住埋寫，兩邊一齊死，正正係團長講嘅「中間層」。

### 修咗乜

* **`api/_registry.js`**：新增 `unitIdVariants()`／`resolveUnitKey()` —— `82`／`082`／`0082`／`00082`
  一律解析到同一個登記 key；`getTrustedUnit()`、`troopEnv()`、`troopShorthand()` 全部改用呢套。
* **`api/proxy.js`**：轉發前把 `payload.unit`（連 `payload.db.unitCode`、`troopId`）**校正做登記咗嗰個編號**。
  唔校正嘅話，寫落 Google Sheet 嘅旅團欄會係「82」，用「0082」讀又搵唔到 ——
  同一張表入面兩套資料庫，兩邊永遠對唔到料（症狀就係「寫咗但讀唔到」）。
* **`assets/js/lib/units.js`**：`unitEntry()` 跨前導零比對；新增 `canonicalUnitCode()`／`canonicalUnitKey()`。
* **`assets/js/main.js`**：閘度打「82」→ `gotoUnit()` 一律用 `0082` 入去，並 toast 話你知「旅團編號已校正：82 → 0082」。
* **`assets/js/lib/store.js`**：`setUnitCode()`／`switchUnit()` 一樣校正（本機資料庫唔會開多一套）。

### 模擬證據（`tests/usersim.mjs`，真 Code.gs ＋ 真 `/api/proxy` ＋ jsdom 真 app）

```
⑤ 用 ?u=82 開（團長打「82」）—— 以前呢度會話「未能連接旅團後端」＝「無後端」
  ✓ ★ 用「82」開都入到登入頁（唔會再話「未能連接旅團後端」）
  ✓ ★ 用「82」開都登入到主控頁
  ✓ ★ 用「82」開都讀到「陳大文」（讀寫兩邊都通）
  · 經代理 dbInfo(0082) 團員＝2　dbInfo(82) 團員＝2（同一個後端，問法差兩個 0）
  ✓ ★ 經代理用「82」同「0082」問到同一套資料（唔會分裂成兩套）
  · 「資料庫」分頁嘅旅團欄值＝["0082"]        ← 冇分裂成「82」
```

## ② 「唔好搞咁多掣要人按」—— 一次儲存＝兩處都寫（而家由**後端**保證）

之前嘅狀況（v2.6.2 以前）：

| 掣 | 寫去邊 | 人喺 Sheet 睇唔睇得明 |
|---|---|---|
| 「儲存到後端」（`saveDb`） | 「資料庫」分頁（分段 JSON） | ✗ 睇唔明 |
| 「更新報表分頁」（`sync`） | 團員／帳目／物資／通告…17 張分頁 | ✓ 睇得明 |

撳完第一粒再開 Google Sheet → 16 張分頁全空 ＋ 一行亂碼 → 「佢話已寫入，但完全冇嘢」。

**而家：`saveDb`／`saveDbCommit` 寫完「資料庫」之後，後端自己即用同一份資料刷新晒報表分頁**
（`refreshReportsFromDb()` → 重用現有 `syncAll()`／`writeTab()`，**冇第二套攤平邏輯**）。

* 呢個係**後端**行為 —— 貼咗 v2.6.3 `Code.gs`，就算前端係舊 cache、或者用家乜都唔識撳，
  一次儲存都係兩處齊齊有嘢。
* 前端亦都識睇 `reports` 回應：後端已經做咗就**唔會**再發第二次請求（慳一半 GAS 配額）；
  舊版 `Code.gs` 冇呢個欄位，前端就會自己補做一次（向下兼容）。
* 自動化／特殊情況可以用 `refreshReports:false` 略過。
* 成功訊息如實講晒寫咗去邊：
  `已儲存到後端 ✓（「資料庫」分頁 2 KB · 報表分頁已更新（5 筆，團員／帳目…嗰啲分頁而家有嘢睇））`

**讀取嗰邊**：`loadFromBackend()` 一次過成份資料庫讀返（分段都會拼齊），所有分頁嘅資料
（團員／帳目／通告／物資／會議／帳戶…）一次到手，冇「呢度讀一半」嘅設計。模擬釘死：

```
⑥ 讀取就讀取曬
  ✓ ★ 全新機登入之後，團員＋帳目一次過讀齊（唔使逐個分頁撳）
     {"members":1,"transactions":1,"notices":0,"invItems":0,"meetings":0,"claims":0,"accounts":2}
```

### 模擬證據：完全冇經前端，後端自己一次過寫齊兩處

```
⑦ 後端自己一次過寫齊「資料庫」＋報表分頁（舊前端／舊 cache 都一樣有效）
  · 直接 saveDb（完全冇經前端）：success=true bytes=2155 reports={"ok":true,"counts":{…}}
  ✓ ★ saveDb 回應話報表分頁都刷新咗
  · 「團員」分頁而家嘅名＝["0082|me_…|…|陳大文…","…李小明…","0082|me_backend_test|2026000777||後端測試員…"]
  ✓ ★ 淨係撳一次儲存（冇撳「更新報表分頁」），團長開 Sheet 即刻見到新團員
```

## ③ 順手拆咗一個潛伏咗兩版嘅炸彈（會**刪走團員進度**）

改 ② 嗰陣全套測試即刻紅燈，查出 `removeSuffixedTabs()`（v2.6.1 加嘅「清後綴分身分頁」）：

```js
if (nm.indexOf(suffix) === nm.length - suffix.length) { ss.deleteSheet(sh); }
```

個名**根本冇嗰個後綴**嗰陣 `indexOf` 回 `-1`，條件就變成 `nm.length === suffix.length - 1`
—— 即係**任何名啱好 4 個字**嘅分頁都會被刪。「進度追蹤」「待批完成」「成員名單」
「同步紀錄」「活動履歷」「待批履歷」「通告全文」全部都係 4 個字。

* v2.6.1／v2.6.2：撳「報表同步」先會中招（團員進度、批核紀錄成批冇咗）。
* v2.6.3 起 `saveDb` 都會刷新報表分頁 —— 唔修嘅話**每次儲存**都會爆。

而家改成嚴格比對結尾、而且要長過個後綴先算，並加咗迴歸測試釘死佢。
