## 1. Code.gs 語法錯誤

**原因**：`gastemplate.js` 用 JS 樣板字串（backtick）產生 `Code.gs`。
入面嗰句 `links.join('\n')` 嘅 `\n` 被樣板字串當成**真換行**，
所以輸出嘅 `Code.gs` 變成：

```js
    (p.photos || []).length, links.join('
'), p.id || ''
```

字串中間斷行 → `SyntaxError: Invalid or unexpected token`（就係你見到嘅 line 158）。

**修正**：寫做 `\\n`，輸出先會係正常嘅 `links.join('\n')`。
同時補返 `var SHEET_TABS = [...]`（舊版本 `doGet` / `doPost` 用咗佢但冇定義，
部署之後一 call `status` 就會 `ReferenceError`）。

順手加咗：
* `action: 'loan'` —— 成員公開頁嘅物資借用申請寫入「物資借用」分頁
* 「報名」分頁新增 **出席與否** 欄（`attendOf()` 由報名欄位抽出）
* 「團員」分頁 fallback 欄位加 `identity`

**驗證**：`tests/smoke.mjs` 用 `vm.Script` 實際 parse 一次產生出嚟嘅 `Code.gs`
（9 項測試，包括「冇字串入面斷行」呢個回歸測試）。

## 3. 防呆（避免即時寫入）

新增 `assets/js/lib/guard.js`，三層保護：

1. **草稿暫存（瀏覽器）**：用戶編輯器、通告編輯器、財務年度設定頁
   所有輸入會自動存去 `localStorage`（key `venture82.drafts.v2`）。
   未撳「儲存」**唔會寫入資料庫**；刷新／撳錯返回都唔會丟失，
   返到去會見到「偵測到未完成嘅草稿 → 還原／放棄」。
2. **打字確認**：刪除用戶要**打低佢個名**先撳到「確定刪除」
   （未打字之前個掣係停用嘅）。
3. **可還原**：刪除／改資料之後，toast 有「**還原**」掣，即刻撈返。

另外，**同步去總表永遠唔會自動發生**：
「每次改動後自動同步」而家只係**排隊**（`sync.pending` 計數），
要去「表格與同步 → 總表同步 → **立即同步全部**」先真正寫入 Apps Script。
成功同步之後計數歸零。

## 8. 首頁帳目（現在結餘 ＋ 期初結餘）

**問題根源**：儀表板「結餘」用 `balance()` = 全部收入 − 全部支出，
**冇加期初結餘**。你嘅帳目由空白開始，舊帳（56 筆）仲未匯入，所以一有支出就即刻變負數。

### 8a. 期初結餘係「逐年」嘅（2026-09-15 修正）

第一版把期初結餘做成**一個全域數字**（`settings.openingBalance`），
再配一個「用舊帳嘅期初結餘（$8,803.28）」一按填入 —— **呢個係錯嘅**。

$8,803.28 係 **2025-26 年度**嘅期初（原表「上年度結餘」）；
而家已經係 **2026-27 年度**，佢嘅期初應該係 **2025-26 嘅期末 $7,846.64**。

| 年度 | 期初 | ＋收入 | −支出 | ＝期末 |
| --- | ---: | ---: | ---: | ---: |
| 2025-26（舊帳 56 筆，2025-06-14 → 2026-01-05） | $8,803.28 | $8,630.00 | $9,586.64 | **$7,846.64** |
| **2026-27（本年度，未有帳目）** | **$7,846.64** | $0.00 | $0.00 | **$7,846.64** |

**修正後嘅做法**（`assets/js/lib/model.js`）：

* 期初結餘存喺 `settings.openingBalances`，**以年度標籤做 key**：`{ "2025-26": 8803.28, "2026-27": 7846.64 }`
* 冇明確設定嘅年度自動**結轉**：`carriedForward(年度開始日)` ＝ 起始底數 ＋ 該日之前所有帳目
* `openingOf(yearKey)` / `openingBalance()`（＝本年度）/ `currentFY()` / `prevFYKey()` / `yearRange()` / `refYearKey()`
* `currentBalance()` = **本年度**期初 ＋ **本年度**收入 − **本年度**支出
  （上年度帳目已計入結轉，**唔會重複加**）
* `balanceBreakdown()` 多咗 `prevYear / prevOpening / prevClosing / referenceYear / referenceClosing / openingMismatch`，
  用嚟對數：本年度期初應該等於上年度期末
* 舊嘅 `settings.openingBalance` 保留做「**第一筆帳目之前**嘅底數」，唔再當所有年度嘅期初

**介面改動**：

* 儀表板帳目卡改成「帳目（現在）· **2026-27 年度**」，欄位寫明「本年度收入／支出」，
  並加一行**上年度**（期初 → 期末），同本年度期初唔吻合會出警告
* 財務「年度設定」（`#/finance/settings`）期初結餘改成**逐年編輯**：
  每年一欄，顯示該年度收入／支出／期末，有「由上年度期末結轉」同「全部自動結轉」掣；
  另有「起始底數（第一筆帳目之前）」欄，並警告**唔好**把上年度結餘填喺度
* 「用舊帳嘅數字填返」一次過填 **2025-26 期初 $8,803.28** ＋ **2026-27 期初 $7,846.64**（唔會再填錯年度）
* 「一鍵匯入舊帳」會同時寫入兩個年度嘅期初（年度由**帳目日期**推斷，唔靠分頁名）
* 兩份財政年度報告改用 `openingOf(range.key)`，各自用自己年度嘅期初

### 8b. 自動修復（`assets/js/lib/store.js` → `migrateOpeningBalances()`）

如果舊資料庫嘅全域 `openingBalance` 啱好等於舊帳參考嘅「上年度結餘」（即係跟咗舊建議填錯年度），

`8803.28 → openingBalances["2025-26"]`、`7846.64 → openingBalances["2026-27"]`，全域欄位還原做 `0`。
已經逐年設定過、或者數字同舊帳唔同，就**唔會**亂搬。
